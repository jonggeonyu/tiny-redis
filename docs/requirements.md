# mini-redis 요구사항

출처: 과제 원문(아래 "원문 요약"), 사용자와 정한 결정. "제안값"은 설계자가 정하고 사용자가 2026-11-09에 승인한 값이다.

## 원문 요약
- 해시 테이블로 키-값 저장소를 직접 만들고, 외부에서 사용할 수 있어야 한다.
- 해시 테이블의 설계 원리, 구현 과정, 주요 함수의 동작을 설명할 수 있어야 한다.
- 기술 스택은 자유롭다. 구현이 우선이며, 핵심 로직은 이해하고 설명할 수 있어야 한다.
- 중점: 동시성 문제가 없는 구조, 만료된 값 요청 처리, API 형태의 구조, 데이터 무효화 방식, (Optional) 서버 다운 시 데이터 보존
- 품질: 저장·조회·삭제 단위 테스트, 외부 사용 기능 테스트(간단한 API의 응답을 mini-redis에 저장해 활용), 엣지 케이스, 캐시 사용 유무 성능 비교

## 기능 요구사항 (1단계)
| ID | 내용 |
|---|---|
| F1 | 해시 테이블을 직접 구현한다. 충돌 처리와 리사이즈를 포함한다. |
| F2 | `SET key value [ttl]`: 값을 저장한다. ttl이 있으면 그 시간 뒤 만료된다. |
| F3 | `GET key`: 값을 돌려준다. 없거나 만료되었으면 "없음"을 돌려준다. |
| F4 | `DEL key`: 키를 지우고 지웠는지 여부를 돌려준다. |
| F5 | `EXPIRE key ttl`: 있는 키에 만료 시간을 설정하고 성공 여부를 돌려준다. |
| F6 | 만료된 값은 어떤 명령에서도 돌려주거나 살아 있는 것으로 취급하지 않는다. |
| F7 | 위 명령을 HTTP API로 외부에 제공한다. |
| F8 | 동시에 여러 요청이 와도 데이터가 깨지지 않는다. |
| F9 | 데모 API 서버: 느린 원본 데이터를 mini-redis에 캐시해 응답한다(cache-aside). 원본 수정 시 캐시를 무효화한다. |
| F10 | 성능 비교 스크립트: 캐시 사용/미사용 결과를 수치로 출력한다. 코드는 발표 화면에 띄울 수 있게 짧고 읽기 쉽게 쓴다. |

## 무효화 방식
- 즉시 무효화: `DEL`
- 시간 기반 무효화: `SET`의 ttl, `EXPIRE`

## 엣지 케이스 (테스트 대상)
**저장소**
- 없는 키 `GET`/`DEL`/`EXPIRE`
- 만료 시각 직전·직후 `GET`, 만료된 키에 `EXPIRE`/`DEL`
- 덮어쓰기 `SET` (ttl 없이 덮어쓰면 기존 만료가 사라진다. 제안값)
- 같은 칸으로 충돌하는 키들의 저장·조회·삭제 (체인 중간 노드 삭제 포함)
- 리사이즈 전후 모든 키 조회
- 빈 문자열 값, 한글·특수문자·공백이 들어간 키, 긴 키

**HTTP 입력**
- 잘못된 JSON, `value`가 문자열이 아님, `ttl`이 0·음수·소수·문자열
- 없는 경로, 지원하지 않는 메서드

**동시성**
1. 클라이언트 수백 개가 동시에 서로 다른 키 수천 개를 `SET` (도중에 리사이즈 발생) → 모두 정확히 조회
2. 같은 키에 동시에 서로 다른 값으로 `SET` → 최종 값은 보낸 값 중 하나
3. 만료 키 삭제와 새 `SET`이 겹침 → 새 값이 살아남음
4. 캐시가 빈 상태에서 같은 요청 100개 동시 도착(cache stampede) → 원본 호출 횟수를 측정해 보여 준다. 방지 기능은 만들지 않는다(제안값).

**캐시(데모 API)**
- 수정(`PUT`) 뒤 조회가 새 값을 돌려줌
- 캐시 ttl이 지나면 원본에서 다시 읽음
- mini-redis가 꺼져 있어도 데모 API는 원본에서 응답한다(제안값)

## 비기능 요구사항
- 외부 라이브러리는 최소로 쓴다. 실행 의존성 없음, 개발 의존성은 Vitest만(제안값).
- 핵심 로직 파일은 설명할 수 있도록 짧게 유지한다.
