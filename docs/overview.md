# mini-redis 개요

## 무엇을 만드나
해시 테이블을 직접 구현한 키-값 저장소를 HTTP API로 외부에서 쓸 수 있게 만든다.
그리고 이 저장소를 캐시로 쓰는 간단한 API 서버로 기능과 성능을 검증한다.

## 왜
크래프톤 정글 과제이다. 결과물을 만드는 것이 최우선이고, 핵심 로직(해시 테이블, 만료, 동시성)은 직접 설명할 수 있어야 한다.

## 발표에서 보여 줄 것 (성공 기준)
- **성능 비교**: 실제 테스트 방식, 테스트 코드, 실행 결과 수치를 화면에 띄운다. 캐시를 쓸 때와 안 쓸 때를 나란히 비교한다.
- **엣지 케이스, 특히 동시성**: 동시에 많은 요청이 와도 데이터가 깨지지 않음을 테스트로 보여 준다.

## 정해진 것
| 항목 | 결정 |
|---|---|
| 언어 / 테스트 | JavaScript (Node.js 22) / Vitest |
| 통신 | HTTP REST |
| 명령 | `SET`(만료 옵션), `GET`, `DEL`, `EXPIRE` |
| 저장소 | 해시 테이블 직접 구현 (JS `Map` 사용 안 함) |
| 영속성 (Optional) | 2단계로 미룸. 1단계는 검토만 문서에 남긴다 |

## 단계
- **1단계**: 저장소, HTTP 서버, 데모 API, 단위·기능 테스트, 성능 비교. 설계: [architecture-phase1.md](architecture-phase1.md)
- **2단계 (선택)**: 영속성. 시간이 남으면 시작한다. 설계는 그때 쓴다.

## 하지 않는 것
- 요구사항에 없는 명령(`TTL`, `EXISTS`, `FLUSHALL`, `INCR` 등)과 다른 자료형(리스트, 해시 등)
- RESP 프로토콜, 복제, 클러스터, 인증
- 메모리 한도와 삭제 정책(eviction)
